# BKGraphics — Руководство по работе с графикой БК через ASCII Matrix API

Специализированная база знаний по созданию спрайтов, заставок и графических ресурсов для советских компьютеров **Электроника БК-0010** и **БК-0011М** (архитектура PDP-11).

Взаимодействие AI с графикой выполняется исключительно через строковый формат **ASCII Matrix**.

---

## 1. Графические режимы БК

Компьютеры БК имеют растровую построчную видеопамять без аппаратных слоёв и текстовых режимов:

| Режим | Разрешение | Цветов | Назначение |
|---|---|---|---|
| `BK0010_COLOR` | **256 × 256** | 4 цвета | Основной цветной режим БК-0010 и БК-0011М (игры, спрайты, заставки) |
| `BK0010_MONO` | **512 × 256** | 2 цвета (ч/б) | Чертежи, САПР, текст высокой чёткости, схемы |
| `BK0011M_COLOR` | **256 × 256** | 4 цвета (из 16 палитр) | Графика БК-0011М с выбором палитры `paletteIndex` (0..15) |

---

## 2. Типичные размеры изображений

* **Спрайты и тайлы персонажей:**
  * `8 × 8` — тайлы лабиринта, пули, монетки, мелкие предметы.
  * `16 × 16` — **базовый стандартный размер** для главного героя и врагов.
  * `24 × 24` и `32 × 32` — крупные персонажи, боссы, портреты диалогов.
* **Полноэкранные заставки (Splash screens):**
  * `256 × 256` в цветном режиме.
  * `512 × 256` в монохромном режиме.

> **Правило кратности:** ширина цветного спрайта должна быть кратна **8 или 16 пикселям** (1–2 машинных слова PDP-11), что обеспечивает максимальную скорость вывода в играх.

---

## 3. Логические цвета и палитры

Цвет в AI API кодируется строго символами ASCII Matrix (не используй RGB, HEX или числовые массивы):

* `K` — **Black** (чёрный, цвет 0, цвет фона).
* `B` — **Blue** (синий, цвет 1).
* `G` — **Green** (зелёный, цвет 2).
* `R` — **Red** (красный, цвет 3).

В монохромном режиме `BK0010_MONO`:
* `K` — чёрный (0).
* `W` — белый (1).

На БК-0011М (`BK0011M_COLOR`):
* Набор из 4 цветов определяется номером палитры `paletteIndex` (0..15). Палитра 0 совместима с БК-0010, палитра 5 даёт контраст чёрный/жёлтый/пурпурный/белый.

---

## 4. Концепция ASCII Matrix

**ASCII Matrix** — это текстовое представление прямоугольной области пикселей:
* Каждая строка текста соответствует горизонтальной строке пикселей.
* Строки разделяются символом перевода строки `\n`.
* Все строки матрицы обязаны иметь **одинаковую длину** (ширину).
* Размеры изображения автоматически определяются из геометрии текста матрицы.
* В матрице используются ТОЛЬКО допустимые цветовые символы (символ `.` запрещён).

### Пример матрицы 16×16 (спрайт персонажа):
```text
KKKKKKKKKKKKKKKK
KKKKBBKKKKBBKKKK
KKKBBBBKKBBBBKKK
KKKBBBBKKBBBBKKK
KKKKBBBBBBBBKKKK
KKKKKGGGGGGKKKKK
KKKKGGGGGGGGKKKK
KKKGGGGGGGGGGKKK
KKKGGGGGGGGGGKKK
KKKKGGGGGGGGKKKK
KKKKKGGGGGGKKKKK
KKKKKKGGGGKKKKKK
KKKKKKKKKKKKKKKK
KKKKKKKKKKKKKKKK
KKKKKKKKKKKKKKKK
KKKKKKKKKKKKKKKK
```

## 5. Работа с графикой BKStudio

При работе с графикой сначала мысленно определи структуру изображения и только затем выполняй операции.

### Основные правила:

1. Используй существующие graphics tools.
2. Для больших однородных прямоугольных областей используй `graphics.fill`.
3. Для небольших сложных, пиксельных или многоцветных деталей используй `graphics.patch`.
4. Не используй множество `set`/пиксельных операций, если ту же задачу можно выполнить одним `fill` или одним `patch`.
5. Перед `patch` убедись, что:
   * ширина всех строк матрицы одинаковая;
   * размеры матрицы соответствуют `width` и `height`;
   * область целиком находится внутри изображения.
6. Учитывай фактическую палитру текущего графического режима. Не используй недоступные цвета.
7. Для симметричных объектов сначала рассчитай одну половину и отрази её логически, вместо независимого проектирования двух половин.
8. Не создавай повторно уже существующий объект. Если объект существует, используй его или создай объект с другим именем.
9. После существенного изменения сложного изображения выполни `graphics.get_region` для проверки результата.
10. Не запрашивай изображение целиком после каждой операции. Проверяй только необходимые области.
11. Не создавай огромные матрицы только ради небольших изменений.
12. Если операция завершилась ошибкой, проанализируй причину и исправь конкретную ошибку. Не повторяй тот же вызов без изменения параметров.
13. Стремись к минимальному количеству tool calls, но не жертвуй корректностью ради минимизации вызовов.
14. После завершения работы кратко сообщи:
    * что создано или изменено;
    * какие graphics tools использованы;
    * были ли ошибки;
    * выполнена ли проверка результата.

### Построение изображения

Перед началом работы разбей изображение на крупные элементы:

* фон;
* рамка или крупные области;
* основные объекты;
* мелкие детали;
* пиксельные детали.

Сначала создай крупную структуру, затем добавляй детали.

Для каждого элемента выбирай наиболее компактное представление:

* одноцветный прямоугольник → `graphics.fill`;
* несколько цветов или нерегулярная форма → `graphics.patch`;
* маленькая пиксельная деталь → небольшой `graphics.patch`.

Не пытайся представить всё изображение одной огромной матрицей.

Если объект симметричный, используй симметрию при расчёте координат.

Не выполняй повторную проверку всего изображения после каждой небольшой операции. После завершения основной структуры достаточно проверить несколько ключевых областей через `graphics.get_region`.

---

## 6. Создание новой графики

Для создания нового спрайта или экрана используй двухшаговый паттерн:

1. **`graphics.create`** — создаёт пустой холст нужного размера и режима в памяти:
   ```json
   { "mode": "BK0010_COLOR", "width": 16, "height": 16, "name": "HERO" }
   ```
   Холст инициализируется нулями на стороне системы. Если имя уже существует, `graphics.create` вернёт ошибку `ERROR_ALREADY_EXISTS`. Модель не должна передавать массивы нулей.

2. **`graphics.set`** или **`graphics.fill` + `graphics.patch`** — заполнение изображения:
   * Для небольших спрайтов (до 16×16): `graphics.set` с подготовленной ASCII-матрицей:
     ```json
     { "name": "HERO", "matrix": "KKKKRRKKKK\nKKKRRRRKKK\nKKRRRRRRKK\nKKKKKKKKKK" }
     ```
   * Для экранов и сложных объектов: `graphics.fill` для фона и крупных блоков + `graphics.patch` для деталей.

---

## 7. Чтение региона

* **`graphics.get_region`** — основной инструмент чтения:
   ```json
   { "x": 0, "y": 0, "width": 16, "height": 16 }
   ```
   Возвращает ASCII-матрицу заданного фрагмента. Используется для анализа перед точечной модификацией.
* **`graphics.get`** — используется **только** для небольших спрайтов (до 32×32).
* Для больших изображений и полных экранов (256×256) **всегда предпочитай `graphics.get_region`**, чтобы не раздувать контекст токенов.

---

## 8. Изменение региона (Patching)

Для точечной правки фрагмента изображения используй трёхшаговый паттерн:

1. **Чтение:** вызвать `graphics.get_region` нужного участка.
2. **Анализ:** определить изменения в ASCII-матрице.
3. **Патч:** применить `graphics.patch` с координатами `x`, `y` и матрицей патча:
   ```json
   {
     "x": 4,
     "y": 4,
     "matrix": "KKRRKKRR\nKRRRRRRR\nKRRRRRRR\nKKRRKKRR"
   }
   ```

* Патч устанавливает реальные цветовые пиксели (символ `.` недопустим).
* Патч строго атомарен: если размеры выходят за границы, холст не повреждается.
* **Экономия контекста:** НЕ вызывай `graphics.get` после каждого `graphics.patch`, если инструмент уже вернул статус успеха (`OK`).

---

## 9. Работа со спрайтами

При создании игрового спрайта:
1. Выбери размер, кратный 8 или 16 (обычно 16×16).
2. Задай режим `BK0010_COLOR`.
3. Задай чёрный фон символами `K` (индекс цвета 0).
4. Нарисуй контур и детали цветами `R` (красный), `G` (зелёный), `B` (синий), `K` (чёрный).
5. Создай спрайт через `graphics.create` → `graphics.set`.

---

## 10. Работа со Sprite Sheet (Листы спрайтов)

Для анимации персонажа (фазы ходьбы, прыжка):
1. Создай объединённый холст кратной ширины (например, `64 × 16` для 4 кадров 16×16 в ряд).
2. Нарисуй кадры целиком через `graphics.set` или последовательно наложи через `graphics.patch` со смещением X: 0, 16, 32, 48.
3. При экспорте в ассемблер укажи сетку спрайтов в параметре `spriteGrid`:
   ```json
   {
     "symbol": "HERO_WALK",
     "spriteGrid": {
       "cols": 4,
       "rows": 1,
       "spriteWidth": 16,
       "spriteHeight": 16,
       "count": 4,
       "symbolPrefix": "HERO_F"
     }
   }
   ```
   Каждый кадр будет экспортирован в отдельную именованную метку (`HERO_F0`, `HERO_F1` и т.д.).

## 11. Экспорт ресурсов и сохранение в проект

После создания графики сохрани её в проект в трёх необходимых представлениях:

### 1) Код или данные для программы БК
* **`graphics.export_asm` / `graphics.export_mac`** — формирует текстовые директивы `.BYTE` в памяти.
* **`graphics.export_bin` / `graphics.export_bks`** — формирует полноэкранный бинарный образ экрана (16388 байт с адресом `040000`).
* **`graphics.add_to_project`** — сохраняет ресурс в файл проекта BKStudio:
  ```json
  {
    "name": "hero",
    "folder": "gfx",
    "format": "ASM",
    "savePng": true,
    "saveState": true,
    "insertInclude": true
  }
  ```
  Форматы: `ASM`, `MAC`, `BIN`, `DAT`, `BKS`, `STATE`, `PNG`.
  Флаг `insertInclude: true` автоматически добавляет `.INCLUDE "gfx/hero.asm"` в активный файл проекта.

### 2) Визуальное изображение для человека (.PNG)
Человеку необходимо видеть созданную графику своими глазами в файловом менеджере или просмотрщике:
* **`graphics.export_png`** (или псевдоним `graphics.save_png`):
  ```json
  {
    "name": "hero",
    "folder": "gfx",
    "scale": 1
  }
  ```
  Сохраняет файл `gfx/hero.png` в проект. Опциональный параметр `scale` (1, 2, 4...) позволяет увеличить мелкие спрайты для лучшей видимости.
  Также доступно авто-сохранение через `"savePng": true` в `graphics.add_to_project`.

### 3) Состояние редактора для человека (.BKGfxState)
Человеку может потребоваться доработать спрайт или экран вручную инструментами кисти/карандаша в GUI:
* **`graphics.save_state`**:
  ```json
  {
    "name": "hero",
    "folder": "gfx"
  }
  ```
  Сохраняет полное состояние редактора `gfx/hero.BKGfxState` в проект. Пользователь может открыть его в редакторе BKStudio через кнопку «📂 Загрузить состояние».
  Также доступно авто-сохранение через `"saveState": true` в `graphics.add_to_project`.
