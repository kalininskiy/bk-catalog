# Спецификация программного API и JSON-RPC протокола отладки BK Emulator

Документ описывает интерфейс интеграции эмулятора БК-0010/БК-0011М с внешними средами: **BKStudio**, локальным **BK Emulator Bridge** и **AI/MCP-клиентами**.

---

## 1. Архитектура взаимодействия

```
┌──────────────────────────────────────────────────────────┐
│                   AI / MCP Client                        │
└────────────────────────────┬─────────────────────────────┘
                             │ MCP (JSON-RPC)
┌────────────────────────────▼─────────────────────────────┐
│                 BK Emulator Bridge                       │
│           (Node.js / Python daemon adapter)              │
└────────────────────────────┬─────────────────────────────┘
                             │ postMessage / WebSocket / CDP
┌────────────────────────────▼─────────────────────────────┐
│                    BK Emulator                           │
│  ├── window.emulatorDebug (программный фасад)            │
│  ├── postMessage listener (обработчик внешних сообщений) │
│  ├── BaseBK001x (память, периферия, платформы)           │
│  └── K1801VM1 (процессор, регистры, выполнение)          │
└──────────────────────────────────────────────────────────┘
```

Эмулятор поддерживает два способа управления:
1. **Прямой JavaScript API** через глобальный объект `window.emulatorDebug` (внутри контекста страницы).
2. **Асинхронный протокол postMessage** (при встраивании в `iframe` или обращении из родительского окна).

---

## 2. Протокол postMessage

Все сообщения передаются через стандартный браузерный `postMessage`.

### 2.1. Входящие сообщения (Host ➔ Emulator)

#### `DEBUG_CALL`
Универсальный вызов любого отладочного метода.
```json
{
  "type": "DEBUG_CALL",
  "id": 101,
  "method": "readMemory",
  "params": ["0o1000", 8]
}
```

#### `DIRECT_LOAD_BIN` (или `LOAD_BIN` с `direct: true`)
Мгновенная программная запись BIN-файла в память без ожидания магнитофонной задержки (4 сек) и набора клавиш.
```json
{
  "type": "DIRECT_LOAD_BIN",
  "id": 102,
  "data": [0, 2, 10, 0, ...],
  "startAddress": "0o1000",
  "autoRun": true,
  "platform": "B10"
}
```
*Примечание:* Поле `data` может быть передано как массив байтов `number[]`, `Uint8Array` или Base64-строка.

#### `LOAD_BIN` (Ленточный режим)
Классическая эмуляция загрузки с кассеты через команды Монитора БК.
```json
{
  "type": "LOAD_BIN",
  "filename": "game.bin",
  "platform": "БК0010",
  "data": [ ... ]
}
```

#### `SET_PLATFORM` / `SET_BOOT`
Программное переключение конфигурации компьютера.
```json
{
  "type": "SET_PLATFORM",
  "id": 103,
  "platform": "B10"
}
```
Допустимые режимы:
- `"B10"` / `"BK0010"` — БК-0010-01 с Вильнюсским Бейсиком в ПЗУ
- `"F10"` — БК-0010 с Фокалом и блоком тестов МСТД
- `"B11"` / `"BK0011M"` — БК-0011М с Бейсиком
- `"base10"` — БК-0010 с Монитором
- `"FDD10"` — БК-0010 с контроллером КНГМД
- `"FDD11"` — БК-0011М с контроллером КНГМД
- `"SMK10"` — БК-0010 с контроллером СМК-512 (ДОЗУ + HDD/FDD)
- `"SMK11"` — БК-0011М с контроллером СМК-512

#### `RESET`
Аппаратный сброс процессора и базовой периферии.
```json
{
  "type": "RESET",
  "id": 104
}
```

#### `SET_THEME`
Установка цветовой темы оформления эмулятора.
```json
{
  "type": "SET_THEME",
  "theme": "bk-crt-green"
}
```

---

### 2.2. Исходящие сообщения (Emulator ➔ Host)

#### `DEBUG_RESPONSE`
Ответ на любой синхронный запрос с идентификатором `id`.
```json
{
  "type": "DEBUG_RESPONSE",
  "id": 101,
  "ok": true,
  "result": [1000, 2040, 0, 0]
}
```
При ошибке:
```json
{
  "type": "DEBUG_RESPONSE",
  "id": 101,
  "ok": false,
  "error": "Адрес вне диапазона 0..65535"
}
```

#### `DEBUG_BREAK`
Событие остановки исполнения при достижении точки останова или шага.
```json
{
  "type": "DEBUG_BREAK",
  "pc": 41184
}
```

## 3. Справочник методов `emulatorDebug`

Все методы доступны через `emulatorDebug.<method>(...)` либо через диспетчер `emulatorDebug.invoke(method, params)`.

### Формат адресов
В параметрах `address` поддерживаются:
- Число (десятичное): `40960`
- Шестнадцатеричная строка: `"0x1000"`
- Восьмеричная строка: `"0o100000"`
- Десятичная строка: `"40960"`

*Важно:* Адресация памяти в архитектуре БК / PDP-11 является **байтовой**. Для доступа к 16-битным словам используются **четные** адреса (`addr & 0xFFFE`), а каждое следующее слово находится по адресу `addr + 2`.

---

### Методы процессора и состояния

#### `getStatus()`
Возвращает полную картину выполнения:
```json
{
  "running": true,
  "pc": 41184,
  "sp": 1000,
  "psw": "CVZN----",
  "cycles": 1284500,
  "breakpoints": [41184],
  "platform": {
    "model": "BK0010",
    "fdd": false,
    "smk512": false
  },
  "tape": {
    "loading": false,
    "filename": ""
  }
}
```

#### `getRegisters()`
Возвращает регистры общего назначения R0–R5, указатель стека SP (R6), счетчик команд PC (R7), биты регистра состояния PSW и такты процессора:
```json
{
  "r0": 0, "r1": 0, "r2": 0, "r3": 0, "r4": 0, "r5": 0,
  "sp": 1000,
  "pc": 41184,
  "psw": "---N----",
  "cycles": 104523
}
```

#### `getPC()` ➔ `number`
Возвращает текущий PC (0..65535).

#### `getSP()` ➔ `number`
Возвращает текущий SP (0..65535).

#### `Stack(count?: number)`
Возвращает дамп слов вокруг текущего SP:
```json
[
  { "address": 996, "value": 0, "isSP": false },
  { "address": 998, "value": 41184, "isSP": false },
  { "address": 1000, "value": 340, "isSP": true },
  { "address": 1002, "value": 0, "isSP": false }
]
```

#### `getSystemRegisters()`
Возвращает актуальное состояние защелок системных портов ввода-вывода (176650..177716):
```json
[
  { "addr": 65456, "name": "Состояние клавиатуры", "write": 64, "read": 64 },
  { "addr": 65458, "name": "Данные клавиатуры", "write": 0, "read": 0 },
  { "addr": 65460, "name": "Скроллинг", "write": 0, "read": 0 },
  { "addr": 65478, "name": "Таймер: начальное значение", "write": 0, "read": 0 },
  { "addr": 65480, "name": "Таймер: счётчик", "write": 0, "read": 0 },
  { "addr": 65482, "name": "Таймер: управление", "write": 0, "read": 65280 },
  { "addr": 65484, "name": "Порт УВВ", "write": 0, "read": 65535 },
  { "addr": 65486, "name": "Внешние устройства", "write": 0, "read": 65535 }
]
```

### Управление исполнением

#### `pause()`
Приостанавливает эмуляцию на текущей инструкции.
Возврат: `{ "paused": true, "pc": 41184 }`

#### `continue()`
Возобновляет эмуляцию до следующей точки останова. Не навязывает открытие UI окна отладчика (`suppressUI`).
Возврат: `{ "running": true }`

#### `step()`
Выполняет ровно одну инструкцию CPU (Step Into). Не навязывает открытие UI окна отладчика.
Возврат: `{ "stepped": true, "pc": 41186 }`

#### `reset()`
Выполняет программный сброс процессора и базовых регистров. Точки останова сохраняются.
Возврат: `{ "reset": true, "pc": 41184 }`

#### `resetAndClear()`
Полный сброс: сброс CPU, очистка страниц ОЗУ (000000–157777) нулями с шагом в слово, снятие всех точек останова.
Возврат: `{ "reset": true, "cleared": true, "pc": 41184 }`

---

### Точки останова (Breakpoints)

#### `setBreakpoint(address: number|string)`
Устанавливает точку останова по адресу слова.
Возврат: `{ "breakpoints": [41184, 42000] }`

#### `clearBreakpoint(address?: number|string)`
Снимает указанную точку останова. Если аргумент опущен или `null`, снимаются **все** точки останова.
Возврат: `{ "breakpoints": [] }`

---

### Память и дизассемблер

#### `readMemory(address: number|string, length?: number)`
Читает `length` 16-битных слов начиная с четного адреса `address` (шаг 2 байта).
Максимальное количество за один запрос: `32768`.
Возврат: `number[]` (массив чисел 0..65535).

#### `writeMemory(address: number|string, data: number[])`
Записывает массив 16-битных слов начиная с четного адреса `address` (шаг 2 байта).
Возврат: `{ "address": 40960, "written": 16 }`

#### `disassemble(address: number|string, count?: number)`
Дизассемблирует `count` инструкций PDP-11 (по умолчанию 16, максимум 256).
Возврат:
```json
[
  {
    "address": 40960,
    "hex": ["012700", "001000"],
    "text": "MOV #1000, R0"
  },
  {
    "address": 40964,
    "hex": ["000000"],
    "text": "HALT"
  }
]
```

---

### Загрузка программ и конфигурация

#### `directLoadBIN(data: number[]|Uint8Array|string, startAddress?: number|string, autoRun?: boolean)`
Прямая запись программы в ОЗУ в обход магнитофона:
- Разбирает стандартный 4-байтный заголовок БК (адрес загрузки + длина)
- Пишет байты тела программы в память
- Если `autoRun: true` (по умолчанию), выставляет PC на `startAddress` (или адрес загрузки) и снимает паузу.
Возврат:
```json
{
  "loaded": true,
  "address": 1000,
  "length": 512,
  "startPC": 1000,
  "autoRun": true
}
```

#### `setPlatform(mode: string)`
Устанавливает модель и конфигурацию БК (`"B10"`, `"F10"`, `"B11"`, `"base10"`, `"FDD10"`, `"FDD11"`, `"SMK10"`, `"SMK11"`) и выполняет `cpu.reset()`.
Возврат:
```json
{
  "platform": "B10",
  "model": "BK0010"
}
```

### Экран

#### `getScreenShot()`
Снимает текущее содержимое канваса эмулятора.
Возврат:
```json
{
  "width": 512,
  "height": 256,
  "format": "png",
  "dataUrl": "data:image/png;base64,iVBORw0KGgoAAA..."
}
```
